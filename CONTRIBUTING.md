# Contributing

Thank you for improving the course.

## Good contributions

- Fix incorrect C examples.
- Improve explanations without making them less precise.
- Add exercises that fit the existing progression.
- Add tests for project behavior.
- Improve accessibility, navigation, or wording.

## Before opening a pull request

- Compile changed C files with warnings enabled.
- Check memory ownership and file handles.
- Verify Markdown links.
- Keep exercise solutions separate from exercise statements.
- Avoid compiler-specific behavior unless clearly labeled.
- Explain why a pedagogical change improves the lesson.

## Style

Use C17-compatible, portable C where practical. Prefer small functions, meaningful names, and comments that explain why rather than narrate obvious syntax.
